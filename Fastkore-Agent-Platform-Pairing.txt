Привязка Fastkore к Agent Platform без ручной правки XML

Контракт для согласования между разработчиками Fastkore и Agent Platform,
11 ноября 2026 года. Меняется первичная настройка подключения. Действующий
обмен одноразового билета на сессию остаётся совместимым.

Что делает администратор

1. В карточке предустановленного сервиса Fastkore Agent Platform указывает
   и сохраняет базовый HTTPS-адрес. В команде «Подключение» выбирает
   «Создать код», затем «Скопировать код и открыть платформу».
   Других полей в ERP не заполняет.
2. Администратор Agent Platform в разделе «Вход из Fastkore» выбирает установку
   ERP с заранее зарегистрированным HTTPS-адресом проверки билета, вводит
   одноразовый код и нажимает «Подключить». Если ERP ещё не зарегистрирована,
   он указывает её HTTPS-адрес проверки билета один раз при регистрации.
3. После подтверждения команда «Подключение» предлагает «Переподключить».
   Её повторное открытие запрашивает текущее состояние с сервера.
   При пустом базовом адресе кнопка ассистента работает в прежнем режиме.
   При заданном адресе без привязки кнопка показывает, что нужна настройка.
   Отдельной галочки включения в ERP нет.

Как работает привязка

- Начать привязку может администратор ERP для фиксированной записи сервиса.
  Перед выпуском кода сервер проверяет HTTPS-адрес платформы и наличие HTTPS
  у собственного сервера. ERP создаёт 32 случайных байта, показывает код
  один раз и хранит в памяти его SHA-256, текущий BaseUrl и срок 5 минут.
  Новый код заменяет прежний. Изменение сохранённой записи сервиса отменяет
  её привязку и ранее выданный код, даже если прежний адрес вернули.
  Замена действующего подключения требует явного
  подтверждения администратора ERP.
- После входа администратора платформы её сервер использует только HTTPS-адрес
  ERP из разрешённой регистрации. Сохраняются проверки назначения, сертификата
  и ограничений исходящих подключений. Запрещены перенаправления при привязке.
  Agent Platform использует уже выпущенный ключ установки. Для новой установки
  она выпускает ключ штатным способом и хранит его в защищённом хранилище.
  Существующий ключ меняется только при явно запрошенной ротации.
- ERP сверяет хеш кода в постоянное время, срок, текущий адрес сервиса,
  platform_origin и согласованность installation_id с verifier. Запрос идёт
  от сервера платформы. Код и проверочное значение не попадают в журналы или
  ответы обычных API. Публичный обработчик ограничивает размер запроса,
  время обработки, частоту и число одновременных запросов.
- Сервер ERP сохраняет verifier с installation_id, связанный HTTPS origin
  и ревизию записи сервиса. В Windows запись хранится в реестре экземпляра
  ERP под HKEY_LOCAL_MACHINE. В Linux — в AgentPlatformBinding.json
  в серверном каталоге, который не должен быть доступен на запись другим
  пользователям. Состояние проверочного значения
  обновляется штатным серверным кодом. Повторный запрос с тем же кодом и теми же
  данными после потери ответа должен вернуть уже полученный результат в пределах
  срока кода. Повтор с отличающимися данными отклоняется. Agent Platform
  сохраняет незавершённую попытку и разрешает вход по новому ключу после
  подтверждения ERP. Если ключ меняется, старые билеты и сессии отзываются по
  действующим правилам. Старый формат ручной настройки остаётся доступен до
  перехода установок на новый способ привязки. После первой привязки через UI
  старый verifier не может снова вступить в силу при очистке или смене адреса.

API между серверами

Agent Platform вызывает POST /api/ai/pair на том же HTTPS origin ERP, который
администратор зарегистрировал для POST /api/ai/validate-ticket. URL строится
сервером платформы из записи установки. Браузер передаёт только ID записи
и код, а endpoint и проверочное значение определяет сервер платформы.
Запрос отправляется с Content-Type: application/json и телом до 4096 байт.

{
  "version": 1,
  "pairing_code": "<43 символа Base64URL без padding>",
  "platform_origin": "https://agentic-platform.fastkore.ru",
  "installation_id": "<UUID существующей регистрации в нижнем регистре>",
  "erp_key_verifier": "fkap1.<тот же UUID>.<64 hex-символа SHA-256>"
}

erp_key_verifier вычисляется из точной полной строки connectionKey, как в
действующем контракте. platform_origin — канонический HTTPS origin без пути,
полученный из серверной настройки Agent Platform. В ответах Cache-Control:
no-store. Успех после сохранения — HTTP 200 и JSON с version: 1, paired: true
и тем же installation_id. Повтор идентичного запроса после потерянного ответа
даёт тот же результат в пределах срока кода. ERP возвращает HTTP 400 для
неверного формата, HTTP 403 для недействительной попытки, HTTP 409 при конфликте
с действующей привязкой, HTTP 429 при лимите и HTTP 503 при ошибке хранения.
Тела ошибок содержат стабильный код, без входных данных и диагностических
подробностей. Agent Platform показывает результат администратору и сверяет
installation_id ответа до отображения статуса «Подключено».

Что реализует Fastkore

- Действие и состояние подключения в существующей карточке сервиса, с серверной
  проверкой прав администратора. Запуск и отображение статуса не требуют
  расширения полей общего справочника или ручной правки XML.
- Короткоживущую попытку привязки, обработчик /api/ai/pair, сохранение привязки
  с проверкой origin при выдаче и погашении билетов. Новое состояние начинает
  действовать после успешной записи. При переоткрытии команды статус берётся
  с сервера, поэтому отдельная команда перезапуска для привязки не нужна.
- Ясные ошибки при заданном BaseUrl без подключения. Действующий контракт
  /api/ai/validate-ticket, WebView2 и синхронизация темы остаются прежними.

Что реализует Agent Platform

- В существующем разделе «Вход из Fastkore» добавить действие для выбранной
  установки. Оно принимает код, сверяет права локального администратора и
  отправляет запрос на сохранённый HTTPS-адрес ERP. Существующая проверка
  доверия к ERP, включая корпоративный CA, обязательна.
- Сервер получает ключ выбранной установки из своего хранилища и вычисляет
  verifier. Запрос привязки, повтор после сетевой ошибки и ответ ERP обрабатывает
  сервер платформы. Ключи и коды не отображаются в обычном статусе установки.
- Состояние подключения показывается в том же разделе. Уже зарегистрированные
  пользователи сохраняют привязку к прежнему installation_id. Проверка билета,
  выдача cookie и подтверждение темы продолжают использовать действующий обмен.

Вход сотрудника после привязки

Fastkore определяет сотрудника по его действующей сессии и создаёт билет
на 60 секунд. Билет связан с попыткой входа в браузере, установкой и адресом
платформы. Agent Platform погашает его на сервере ERP существующим вызовом
POST /api/ai/validate-ticket. Для десктопа переход остаётся в WebView2.
Для Web ERP понадобится отдельная кнопка и переход через браузер с той же
серверной выдачей билета, привязкой попытки и выдачей сессии платформы.
Запуск из Web ERP предстоит реализовать и проверить отдельно.

Поле «Временный токен» (AccessToken) в общем справочнике сервисов хранит
одно значение на запись. Для одновременных входов нескольких сотрудников
используется существующий серверный буфер одноразовых билетов. Код привязки
тоже живёт на сервере и имеет отдельный короткий срок. TLS проверяет сервер
на каждом HTTPS-соединении. Полномочие привязать установку даёт одноразовый
код, а полномочие погасить билет — уже существующий ключ установки.

Проверка перед выпуском

- Чистая установка подключается с одним заполненным полем в ERP и без
  редактирования Configuration.xml. При отключённом TLS экран объясняет,
  какое штатное соединение требуется.
- Код истёк, уже использован для других данных или выпущен для старого
  BaseUrl: привязка отклоняется. Два параллельных запроса дают один результат.
- Потеря ответа после сохранения и повтор запроса не меняют ключ произвольно.
  Ошибка записи не включает вход. Смена origin блокирует погашение старых билетов.
- Текущие подключения с ручными настройками продолжают работать до перехода.
- Два сотрудника входят параллельно, каждый под своей учётной записью.
  Проверки повторного использования билета, отзыва и прав выполняются
  отдельно для настольного клиента и для Web ERP после добавления его кнопки.
