# FreeCAD в чате

Добавьте `-f compose.freecad.yaml` к обычной команде Compose с оверлеем `compose.codex.yaml`.
Соберите и запустите сервисы `app`, `codex` и `freecad`. Скрипт `deploy/Update-TestStack.ps1`
подключает оверлей в тестовом стеке. Приложение передаёт параметры и предыдущую версию
документа через Unix-сокет. Контейнер FreeCAD работает без сети и томов с проектами.
У каждого построения своя временная папка.

Откройте чат с разрешённой записью и инструментом **Вложения и файлы ответа**.
Отправьте два сообщения в одном чате.

1. «Собери шарнирную тягу с двумя вилками и болтами М12, межосевое расстояние 86 мм».
2. «Измени межосевое расстояние этой сборки на 100 мм».

Каждый ответ содержит редактируемый FCStd и GLB для вращения в чате. При изменении
размера сервис открывает последнюю доступную сборку, которую он выдал в этом чате.
Для изменения требуются текущие права на чат и создание файлов. Предыдущие версии остаются в своих сообщениях.

В FreeCAD выберите **Параметры тяги → Geometry → PivotDistance**, укажите длину
и пересчитайте документ. Длина тяги, положение второго отверстия и пяти компонентов
правого шарнира зависят от этого параметра. Диапазон шаблона составляет 40–2000 мм.
Готовый шаблон содержит 11 компонентов пяти типов. Болт с винтовой
резьбой и гайка используют геометрию демонстрационной сборки М12 из двух файлов
Open CASCADE B-rep. Тяга построена из собственных объектов и операций FreeCAD.
Для открытия FCStd достаточно стандартной установки FreeCAD.
## Проектирование по описанию и чертежам

`freecad_design` создаёт пустой документ, открывает предыдущий результат чата или выбранный FCStd из вложений. Команда `inspect` возвращает дерево, размеры признаков, габариты видимых компонентов и записанные идентификаторы ERP. В режимах `create` и `edit` модель передаёт скрипт Python для штатного API FreeCAD: эскизы, выдавливания, вращения, отверстия, булевы операции, геометрические преобразования и экземпляры. Результат определяется выполненным скриптом. Для ручной правки размеров предпочтительны нативные операции и выражения. Детали из вложенных STEP, BREP и FCStd можно использовать через словарь `input_files`.

Построение и повторное открытие для экспорта идут в отдельных процессах bubblewrap. Доступны библиотеки FreeCAD и каталог одного задания. Сокет сервиса, каталоги других запросов, сеть и учётные данные ERP отсутствуют в песочнице. Ошибка FreeCAD передаётся модели для исправления. При успешной проверке чат публикует FCStd и самостоятельный GLB.

Модель со зрением получает приложенные изображения. Для CAD-запроса с PDF платформа передаёт изображения первых четырёх листов каждого документа в пределах общего лимита изображений. В контексте указывается фактическое покрытие. Для точной реконструкции нужны читаемые размеры и достаточные виды.

Для сопоставления с BOM функция `bind_item(obj, item_id, part_number, entity_set_id, installation_id, entity_uri)` сохраняет внешние ссылки в свойствах детали. Первые два аргумента обязательны. Параметры установки и карточки берутся из подтверждённых данных ERP. Экспорт GLB сохраняет эти свойства в `node.extras`. Публикацию в ERP выполняют разрешённые операции конкретной установки.
