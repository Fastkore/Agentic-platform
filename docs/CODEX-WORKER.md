# Отдельный исполнитель Codex

Для текстовых чатов и лимитов запустите платформу вместе с исполнителем:

```powershell
docker compose -f compose.yaml -f compose.codex.yaml up -d --build --wait
```

Вход в ChatGPT выполняется в контейнере исполнителя:

```powershell
docker compose -f compose.yaml -f compose.codex.yaml exec codex codex login --device-auth
```

Терминал покажет официальный адрес и одноразовый код. Войдите в выбранный рабочий аккаунт ChatGPT и введите код на странице OpenAI. Если рабочая область отключила вход по коду, его включает администратор ChatGPT. Состояние входа можно проверить той же командой Compose, заменив `login --device-auth` на `login status`. Приложение подхватит подключение при следующей проверке.

При использовании Happ на хосте Docker Desktop задайте `BRIDGE_CODEX_HTTPS_PROXY=http://host.docker.internal:10809` в `.env`, подставив фактический HTTP-порт Happ. Параметр используется только контейнером исполнителя, в том числе при входе и чтении лимитов. После изменения параметра пересоздайте контейнер `codex`.

Codex хранит авторизацию и историю CLI в томе `codex_auth`, доступном только контейнеру исполнителя. Платформа и исполнитель обмениваются сообщениями через локальный Unix-сокет, который не публикуется в сеть. Для режима чтения исполнитель получает текстовые выдержки из вложений и файлов проекта.

Для задач, которым нужно создавать файлы, включите «Настройки → Сервер → Рабочая папка агента» и разрешите запись в профиле специалиста. Платформа создаёт папку на задание в общем временном томе размером 256 МБ. В неё попадают копии вложений, недавних результатов чата и разрешённых файлов проекта. Песочница разрешает запись в папку текущего задания. Готовые файлы из `output` сохраняются в выбранном хранилище и скачиваются из ответа в чате. Можно сохранить до 8 файлов, до 20 МБ каждый и до 60 МБ суммарно. Проект с вложенными папками сохраните архивом. Рабочая папка удаляется после задания.

Образ закрепляет версию Codex CLI. Профиль `deploy/codex-seccomp.json` основан на [стандартном профиле Moby, 6049e400](https://github.com/moby/profiles/blob/6049e40058759e8a1673ac1090ec6a7e36b9c9bd/seccomp/default.json), Apache-2.0. Дополнительно разрешены вызовы для создания пространства имён пользователя и операции с монтированием, нужные bubblewrap. Контейнер запускается без Linux capabilities с включённым no-new-privileges. Профиль Codex исключает каталог авторизации и сокет из песочницы.

Для совместного пилота Fastkore можно добавить `-f compose.sso.yaml` в команду запуска, когда конфигурация ERP готова. [Настройка SSO](FASTKORE-SSO-PILOT.md).
# Fastkore CLI для Linux

Распакуйте поставку 27.0.48.0 SSO в `private/fastkore-cli-pilot/27.0.48.0-sso` и проверьте `SHA256SUMS`. Скопируйте туда `deploy/fastkore-cli-pilot.Dockerfile` под именем `Dockerfile.pilot` и `deploy/fastkore-cli-pilot.mjs`. Для `Dockerfile.pilot.dockerignore` используйте правила `.dockerignore` пакета с дополнительной строкой `!fastkore-cli-pilot.mjs`. Проверьте адрес gRPC TLS в Compose и CA в `private/fastkore-ca/ca.pem`. Они должны совпадать с доверенной привязкой ERP.

Создайте volume `fastkore_cli_ticket_socket` и запустите `docker compose -p fastkore-cli -f deploy/compose.fastkore-cli-pilot.yaml up -d --build cli`. При запуске платформы добавьте `-f compose.fastkore-cli-worker.yaml`. Unix-сокет доступен backend и исполнителю Fastkore CLI. Проверка запуска доступна локальному администратору по `GET /api/admin/fastkore/cli-pilot`. В SSO-чате `fastkore_cli_describe` возвращает офлайн-описания.

После обновления ERP с маршрутом `POST /api/ai/cli-ticket` включите `BRIDGE_FASTKORE_CLI_TICKETS=1` и пересоздайте контейнер приложения. Для каждого вызова `data get` или `data query` backend получает отдельный билет сотрудника. Исполнитель передаёт его через stdin. Запросы CLI к спискам с фильтрами или ограничениями, которые исполнитель не может воспроизвести, не выполняются.
