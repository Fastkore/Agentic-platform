# Отдельный исполнитель Codex

## Подключение Codex через ChatGPT

1. Войдите в нужный экземпляр платформы как администратор. Откройте **Настройки → Сервер и AI → Подключения к AI → Аккаунты исполнителей**.
2. Проверьте поле **HTTPS-прокси**. Первоначальный адрес берётся из настроек контейнера. Кнопка **Сохранить прокси** применяет адрес к следующим подключениям и заданиям всех агентов Codex этой установки. Пустое поле включает прямое соединение. Сохранённое значение переживает перезапуск исполнителя.
3. В строке **ChatGPT** нажмите **Вход → Получить код**. Для нового аккаунта нажмите **Добавить аккаунт**, выберите **ChatGPT**, укажите название и нажмите **Получить код**.
4. Когда появится код, откройте **Войти в ChatGPT**, выберите нужную учётную запись и введите код на странице OpenAI. При закрытии окна мастера вернуться к действующему коду можно кнопкой **Продолжить вход**.
5. Вернитесь в мастер. После подтверждения он обновит список. Проверьте отметку **Активен**. Если завершили вход при закрытом мастере, включите аккаунт этой отметкой. В новом чате выберите модель Codex и отправьте короткий вопрос.

Если код не появился и мастер показывает **HTTP 403**, OpenAI отклонил запрос с сервера до выдачи кода. Проверьте доступ исполнителя к `auth.openai.com`, адрес прокси в этой установке и повторите запрос. При тайм-ауте проверьте доступность прокси из контейнера. Если код уже появился, но ChatGPT отказывает при подтверждении, проверьте разрешение на вход по коду устройства в настройках безопасности личного аккаунта или в разрешениях рабочей области. [Вход по коду устройства](https://developers.openai.com/codex/auth/#login-on-headless-devices)

Antigravity показывает ссылку Google, затем принимает код со страницы авторизации.
Сотрудникам видны модели аккаунтов с отметкой **Активен**.
Аккаунты и авторизации хранятся в закрытом томе исполнителя.
Снимите отметку **Активен**, чтобы остановить задания этого аккаунта и сохранить вход.
Кнопка корзины останавливает его задания и удаляет сохранённый вход. Подключить аккаунт заново можно через **Добавить аккаунт**.
Сеансы модели
разделяются по активному аккаунту. Рабочие файлы CLI остаются привязаны к чату.
При переходе между исполнителями общий выбор модели сбрасывается на автоматический.
Если в чате или профиле агента явно задана модель, выберите совместимую модель.

## Что получает агент при отправке вопроса

1. Платформа определяет автора, проект, профиль агента и доступные этому запуску источники. Основному агенту и агенту для консультации собираются отдельные наборы инструментов.
2. В инструкции входят общие правила установки, правила рабочей роли, текст профиля и его файлы инструкций. Платформа добавляет применимые правила о личных указаниях, выдаче материалов библиотеки, работе с файлами и подготовке ответа.
3. В начале запроса указаны проект, название и назначение агента, режим чата и способ выдачи результата. У вошедшего через Fastkore сотрудника может быть снимок текущего экрана. Его подписи и технические поля берутся из вопроса, включая случаи ожидания в очереди.
4. Инструмент `knowledge` ведёт к разделам Fastkore и компании. При старте сессии или обновлении базы агент получает памятку и список документов. Подключённые папки библиотеки проекта видны по названиям. Полный перечень разрешённых папок, их назначение, покрытие поиска и правила выдачи доступны через `library_list`.
5. В личном чате владельца могут применяться его указания и каталог подходящих приёмов. Вложения перечисляются по имени. При доступе к рабочей папке исполнитель читает файлы из `input` и выдаёт результат через `output`. Изолированный исполнитель без рабочей папки получает извлечённый текст документов и поддерживаемые изображения.
6. При продолжении чата платформа использует сессию исполнителя или добавляет разрешённую недавнюю переписку. Текст нового вопроса завершает запрос. В консультации на этом месте стоит подзадача от основного агента.

Для проверки реальными моделями служит `tests/fastkore-context.smoke.mjs`. После сборки сервера запустите его через Node с `BRIDGE_EXECUTION=isolated`, путём `BRIDGE_CODEX_SOCKET` к тестовому исполнителю и идентификатором `FASTKORE_TEST_MODEL` из его каталога. Скрипт создаёт временный проект, проверяет вызовы на тестовых записях ERP и сверяет ответы модели. Документы для проверки поиска загружаются во временные базы компании и проекта.

## Аккаунт GLM (Z.ai)

Для GLM вход выполняется ключом API из подписки GLM Coding Plan
(личный кабинет Z.ai → Plan Overview). Создайте аккаунт типа
«GLM · Z.ai (ключ)», вставьте ключ и нажмите «Сохранить ключ».
Ключ хранится только в закрытом томе исполнителя, используется как
провайдер ZAI в Codex CLI и не возвращается интерфейсом. Смена ключа
начинает новые сеансы модели. Адрес API Z.ai при необходимости
переопределяется переменной `BRIDGE_GLM_BASE_URL` (по умолчанию
`https://api.z.ai/api/v1`). Остаток лимита GLM платформой не отображается.

## Аккаунт GigaChat (Сбер)

В аккаунтах исполнителей выберите «GigaChat · Сбер (ключ)». Введите Authorization Key
проекта GigaChat API и выберите его Scope. Сервер проверит ключ, загрузит каталог
доступных моделей и сохранит ключ только в закрытом томе исполнителя.

GigaChat обращается напрямую к API Сбера. Исполнитель вызывает разрешённые
инструменты платформы, возвращает их результаты модели и передаёт поток текста
и событий в чат. Продолжение чата использует опубликованную историю платформы.
В задачах с разрешением на запись доступны файлы и офисные инструменты текущего
задания. Для моделей с поддержкой изображений доступны вложения JPG и PNG до 15 МБ.

Публичные сертификаты из `deploy/gigachat-ca.crt` используются только для соединений
с API и сервером авторизации GigaChat. [Справка Сбера о сертификатах](https://developers.sber.ru/docs/ru/gigachat/certificates)

Для текстовых чатов и лимитов запустите платформу вместе с исполнителем:

```powershell
docker compose -f compose.yaml -f compose.codex.yaml up -d --build --wait
```

Для диагностики основного профиля администратор может отдельно запустить вход в терминале контейнера. Для именованных аккаунтов используйте мастер, который задаёт каталог выбранного профиля.

```powershell
docker compose -f compose.yaml -f compose.codex.yaml exec codex codex login --device-auth
```

Терминал покажет официальный адрес и одноразовый код. Войдите в выбранный рабочий аккаунт ChatGPT и введите код на странице OpenAI. Если рабочая область отключила вход по коду, его включает администратор ChatGPT. Состояние входа можно проверить той же командой Compose, заменив `login --device-auth` на `login status`. Приложение подхватит подключение при следующей проверке.

Для первоначального адреса при использовании Happ на хосте Docker Desktop задайте `BRIDGE_CODEX_HTTPS_PROXY=http://host.docker.internal:10809` в файле окружения конкретного Compose-проекта, подставив фактический HTTP-порт. Адрес, сохранённый в мастере платформы, имеет приоритет. Терминал `docker compose exec` наследует окружение контейнера, а мастер использует текущую настройку платформы.

Codex хранит авторизацию и историю CLI в томе `codex_auth`, доступном только контейнеру исполнителя. Платформа и исполнитель обмениваются сообщениями через локальный Unix-сокет, который не публикуется в сеть. Для режима чтения исполнитель получает текстовые выдержки из вложений и файлов проекта.

Для задач, которым нужно создавать файлы, включите «Настройки → Сервер → Рабочая папка агента» и разрешите запись в профиле специалиста. Платформа создаёт папку на задание в общем временном томе размером 256 МБ. В неё попадают копии вложений, недавних результатов чата и разрешённых файлов проекта. Песочница разрешает запись в папку текущего задания. Готовые файлы из `output` сохраняются в выбранном хранилище и скачиваются из ответа в чате. Можно сохранить до 8 файлов, до 20 МБ каждый и до 60 МБ суммарно. Проект с вложенными папками сохраните архивом. Рабочая папка удаляется после задания.

Образ закрепляет версию Codex CLI. Профиль `deploy/codex-seccomp.json` основан на [стандартном профиле Moby, 6049e400](https://github.com/moby/profiles/blob/6049e40058759e8a1673ac1090ec6a7e36b9c9bd/seccomp/default.json), Apache-2.0. Дополнительно разрешены вызовы для создания пространства имён пользователя и операции с монтированием, нужные bubblewrap. Контейнер запускается без Linux capabilities с включённым no-new-privileges. Профиль Codex исключает каталог авторизации и сокет из песочницы.

Для совместного пилота Fastkore можно добавить `-f compose.sso.yaml` в команду запуска, когда конфигурация ERP готова. [Настройка SSO](FASTKORE-SSO-PILOT.md).
# Fastkore CLI для Linux

Рабочие файлы CLI используют общий с Codex том заданий. Укажите имя тома в
`BRIDGE_CODEX_JOB_VOLUME`, если Compose-проект платформы отличается от
`agentic-platformin`. CLI работает с UID/GID 1000 и видит текущее задание
в `/runner/jobs/{runId}/cli`. Команды получают рабочую папку от backend.
Пользовательские параметры соединения и билеты в аргументах не принимаются.

Каталог `cli` сохраняется в локальном `/data/cli-workspaces` отдельно по
установке, сотруднику, проекту и чату. Исходники размещаются в `source`,
резервные копии в `backups`, промежуточные файлы в `tmp`.
Лимит одного чата составляет 128 МиБ и 10 000 файлов, общий лимит — 2 ГиБ.
При сохранении удаляются рабочие каталоги, не использовавшиеся 30 дней.
Для долговременного результата агент копирует нужные файлы в `output`.
После успешного сохранения локального каталога временная папка задания удаляется.
При ошибке сохранения временная папка сохраняется для восстановления и задание
сообщает об ошибке. MinIO используется для опубликованных файлов по настройкам
хранилища платформы.

Модель получает полный каталог MCP от доверенного сервера ERP. Для CLI доступны
`fastkore_cli_catalog`, `fastkore_cli_command_describe` и
`fastkore_cli_execute`. Параметры передаются массивом, команда запускается
через execFile с отдельным билетом сотрудника. Fastkore проверяет права ERP.
Файловые параметры CLI ограничены каталогом текущего задания.
Переключатели «Разрешить Fastkore MCP» и «Разрешить Fastkore CLI» в карточке
установки по умолчанию включены. Профиль агента и подключения проекта также
должны разрешать инструмент Fastkore ERP.

Импортируйте Linux-архив `27.0.62.0` SSO через `deploy/Import-FastkoreCli.ps1`. Скрипт проверит `SHA256SUMS` и разложит пакет в `private/fastkore-cli-pilot/27.0.62.0-sso`. Сборка использует каталог поставки и файлы из `deploy`. Для другой установки укажите `BRIDGE_FASTKORE_CLI_SERVER=grpc://host:port` в `.env`. Адрес и публичный CA из `private/fastkore-ca/ca.pem` должны совпадать с доверенной привязкой ERP. [Документация Docker Compose](https://docs.docker.com/reference/compose-file/build/#additional_contexts)

`BRIDGE_FASTKORE_CLI_STDOUT_MAX_BYTES` задаёт предел чтения stdout в байтах и по умолчанию равен 8 МиБ. Укажите одно значение для приложения и исполнителя. `fastkore_cli_execute` принимает необязательный массив `fields` с путями внутри `data`, например `data.templateSha256`. После выбора полей лимит JSON для модели по умолчанию составляет 96 000 символов. `maxResponseChars` принимает целое число от 96 000 до 200 000 и меняет лимит только для текущего вызова. Коды `cli_stdout_too_large` и `response_too_large` указывают, какой предел достигнут. Код завершения и, если доступна, диагностика частичного результата сохраняются. Для чтения определения формы перед генерацией PDF используйте `report definition show --detail brief --json`.

Для CLI через SSO сервер Fastkore должен выдать делегирование текущему сеансу сотрудника. Разрешите CLI в настройках установки и роли. Подключённый исполнитель получает билет на команду после проверки адреса и сертификата ERP. При отсутствии делегирования проверьте серверную привязку и совместимость поставок. Указывайте путь в интерфейсе только после проверки на целевой версии. Выполните команды из корня репозитория.

```sh
docker volume create fastkore_cli_ticket_socket
docker compose -p fastkore-cli -f deploy/compose.fastkore-cli-pilot.yaml up -d --build --wait cli
docker compose -f compose.yaml -f compose.codex.yaml -f compose.sso.yaml -f compose.fastkore-cli-worker.yaml up -d --build --wait
```

На действующей установке используйте её имя Compose-проекта и добавьте используемые там дополнительные файлы Compose. Исполнитель проверяет каталог команд CLI перед открытием Unix-сокета. Локальный администратор может проверить запуск по `GET /api/admin/fastkore/cli-pilot` через настроенный HTTPS-адрес платформы.

## Сквозная проверка MCP и CLI

1. Укажите HTTPS-адрес `/webapi/mcp` в настройках установки. В проекте включите инструмент Fastkore ERP для нужного профиля агента. Заново откройте помощника из Fastkore после настройки доступа.
2. Попросите агента вызвать `fastkore_GetCurrentUserInfo` через MCP и `fastkore_cli_auth_info` через CLI. Сверьте обе личности с сотрудником в ERP. Проверка CLI вернёт GUID только после его сверки с текущим SSO-сеансом.
3. Для известного тестового объекта вызовите подходящий инструмент чтения MCP и `fastkore_cli_data_get` из карточки. Для списка без ограничений проверьте `fastkore_cli_data_query` с небольшим лимитом. Для каждой команды CLI платформа получает отдельный билет у `POST /api/ai/cli-ticket` и передаёт его в stdin.
4. Повторите проверку под сотрудником с другими правами и убедитесь, что объект вне его прав недоступен. После отзыва делегирования в ERP новый токен MCP или билет CLI должен отклоняться.

В режиме справки `fastkore_cli_describe` показывает описание команд. Исполнение CLI требует действующего делегирования и совпадения адреса и CA. Для обычного воспроизводимого списка агент может вызвать `fastkore_cli_execute` с командой `data query` и параметрами `["--context","context.json"]`. При чтении через MCP схема выбранной операции должна поддерживать всю запрошенную область. Для других объектов агент выбирает операцию и параметры по контракту текущего сеанса. Каждый вызов выполняется с правами сотрудника в ERP.
