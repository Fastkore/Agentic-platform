5. ПРОВЕРКА НА СТЕНДЕ (B7, E6, F3)
Запуск (из корня репозитория, на хосте Docker):

  (или двойной щелчок work\project-sources-agent\run-stand.cmd — пишет журнал в work\project-sources-agent\stand-run.log)
Флаг -SkipUpdate — не пересобирать, только проверки. Итог: work\project-sources-agent\stand-report.json.
Критерии приёмки по полям отчёта:
- storage: ok=true, kind="s3", bucket="agentic-platform-sources".                       → B1/B7
- minioIntegration: "# fail 0" и "# skipped 0" (тест реально шёл против MinIO).        → B7
- executorIsolation: storageEnvNames=[], minioResolvable=false, sourcesDb=false,
  readOnlyRoot=true, hostMinioReachable=false.                                          → E6
- executorNetworks: нет сети agentic-platformin_file_storage.                           → E6
- backup / verifyBackupCopy: без ошибок, verify подтверждает размеры и хеши объектов; resume — сборщик снова работает. → F3, AC13
Если E6 полностью зелёный — можно включить закрытый анализ: в .env стенда BRIDGE_SOURCES_CLOSED_ANALYSIS=verified, переразвернуть, проверить, что restricted-источник теперь доступен специалисту на изолированном исполнителе, а на неизолированном — по-прежнему отказ. Если хоть одно поле не прошло — НЕ включать, записать в TODO как блокер.
E3 (журналы): загрузить маленький тестовый каталог с уникальной строкой-маркером, задать по нему вопрос в explanation_only, затем:
  docker compose -p agentic-platformin logs app codex | findstr <маркер>
Маркер не должен встречаться в журналах и в выданном ответе.
