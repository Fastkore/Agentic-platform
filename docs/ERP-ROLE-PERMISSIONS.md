# Доступ к Fastkore MCP и CLI

В «Настройки → Роли» прямо на карточке находятся четыре синих переключателя:
MCP, CLI, «Поиск и чтение» и «Внешние запросы». Изменения сохраняются сразу.
MCP и CLI по умолчанию включены, оба интернет-разрешения выключены.

Настройки хранятся по installation_id и GUID роли. Переименование роли их не сбрасывает.
Удаление роли из отображаемого каталога также не удаляет сохранённую политику.
При нескольких ролях разрешение достаточно получить хотя бы от одной роли.
Для совместимости с действующим тестовым режимом новые роли, пустой набор ролей и
старые серверы без user.roles по умолчанию допускают оба подключения.

Эти разрешения являются дополнительным фильтром. Fastkore ERP также должен быть
включён в профиле специалиста и в подключении этого специалиста к проекту.
Установка Fastkore имеет отдельные общие переключатели MCP и CLI.
Рабочий сеанс должен происходить из Fastkore с действующим делегированным доступом.
Авторизация аккаунта Codex, Google или Z.ai не предоставляет доступ к ERP.

При вызове инструмента платформа повторно проверяет сеанс и актуальные разрешения
ролей. Fastkore проверяет операции над своими объектами от имени сотрудника.
Служебные каталоги исполнителя не являются способом доступа к Fastkore CLI:
агент получает инструменты fastkore_cli_* и fastkore_* через платформу.

API: PATCH /api/admin/erp-roles/:installationId/:roleId/permissions
с телом {"mcp":true,"cli":true,"webRead":false,"webRequests":false,"revision":0}. Требуется администратор платформы.
Несовпадающая revision возвращает 409. Каждое изменение записывается в журнал.

# Очереди исполнения

По умолчанию GLM допускает два параллельных хода, остальные провайдеры — по одному;
общий предел основных ходов — четыре. Ходы одного чата сохраняют FIFO даже при смене
провайдера. Очередь фиксирует провайдера автовыбора при постановке задания.
Консультация связана с конкретным вызовом родителя и наследует только его отмену.
Если целевой провайдер специалиста занят другим ходом, консультация отклоняется,
а не создаёт взаимную блокировку. Отмена одного родителя не останавливает другого.

Сам исполнитель Fastkore CLI допускает четыре отдельных процесса с независимыми
stdin, отменой и рабочими папками заданий. BRIDGE_FASTKORE_CLI_CONCURRENCY меняет
этот предел (1–16). BRIDGE_GLM_CONCURRENCY и BRIDGE_EXECUTOR_CONCURRENCY задают
параллельность GLM и общий предел. Локальные проверки используют имитаторы.

# Внешний интернет

Инструменты общие для Codex, Antigravity и GLM. internet_search использует официальный
MCP поиска Z.ai с ключом активного GLM Coding Plan; ключ остаётся на исполнителе.
internet_read читает публичную страницу методом GET. internet_request выполняет
явно заданные HTTP-запросы, включая POST/PUT/PATCH/DELETE. Права повторно проверяются
при вызове и перед возвратом результата. Разрешение поиска/чтения не включает API-запросы.

Сетевой доступ shell не расширяется. Интернет-инструменты не обращаются к внутренним,
локальным и служебным адресам, в том числе через редиректы и подмену DNS. Платформенные
ключи и cookie не подставляются в запросы. Запрос к API может содержать явно переданные
сотрудником заголовки и тело. Для неизвестной документации агент сначала ищет ссылки,
для известной — сразу читает страницу. Тексты сайтов являются данными, не инструкциями.

# Текст в процессе ответа

Публичные сообщения модели поступают в чат по мере получения. Codex/GLM используют
agentMessage/delta, Antigravity — agent_response, Gemini — assistant message. Итоговый
снимок заменяет накопленный текст, чтобы избежать повторов. Внутренние reasoning-события
не выводятся. При работе инструмента интерфейс показывает его название.
