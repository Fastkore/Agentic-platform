1. ЦЕЛЬ И НАЗВАНИЯ

Универсальная библиотека клиентских документов, инструкций, таблиц и исходников. Управляющий загружает и обновляет материалы, сотрудник задаёт вопросы, агент исследует разрешённые файлы и объясняет ответ с основаниями. У каждой папки одно актуальное содержимое.

«Настройки → Библиотека» — все доступные папки и проекты, к которым они подключены.
«Проект → Библиотека» — папки проекта, состояние обработки и доступ специалистов.
Внутри именованные папки, например «Документация», «Договоры», «Fastkore Platform», «Fastkore Business».
«Проекты» остаётся отдельным пунктом управления проектами.

Техническое пространство имён подсистемы — library. Использовать server/library, shared/library.ts, LibraryPanel, ProjectLibraryDialog, LibraryUploadPanel и library_* для инструментов. Именованный набор — LibraryFolder с folderId. API начинается с /api/library и /api/projects/:projectId/library, настройки окружения относятся к BRIDGE_LIBRARY_*.
Исправить импорты, тесты, Compose и документацию. Общие слова source в авторизации, ERP и других подсистемах не переименовывать. Прежние имена хранилища учитывать только при разовом переносе данных.

2. ГРАНИЦЫ И УДАЛЕНИЕ ЛИШНЕГО

Обязательны загрузка, обновление, чтение как каталога, извлечение документов, поиск, ответы с основаниями, подключение к проектам и серверные права.
Удалить из действующего интерфейса, API, агентских инструментов и модели продукта:
- пользовательские версии и историю снимков;
- наборы совместимых версий и зависимости релизов;
- закрепление версий за чатом и переключение между ними;
- исторические прайсы, периоды действия, выбор на дату и проверки пересечений периодов;
- бизнес-календарь библиотеки и правила удержания старых снимков;
- обязательный анализ символов и графов вызовов;
- специальные нагрузочные инструменты на 10 ГиБ и продуктовый мастер миграции legacy Dataset.

Прайс обрабатывается как актуальная таблица. Для папки нужны описание и дата последнего успешного обновления. Номер релиза вводить не требуется. Старые маршруты после переноса отключаются, историческое содержимое через них недоступно.
Существующую работающую загрузку, MinIO, структуру файлов и проверки доступа переиспользовать. Переписывание всей подсистемы с нуля не является задачей.

3. ОБЪЕДИНЕНИЕ С ПРОЕКТНЫМИ ФАЙЛАМИ

Новая библиотека заменяет ProjectFilesDialog и инструменты project_files_list/read. В проекте остаётся один вход «Библиотека».
Существующие библиотечные файлы перенести однократно с сохранением содержимого, назначений специалистам и прав скачивания. Если раньше доступ ограничивался отдельными файлами, сохранить эквивалентное ограничение, не открывать всю папку автоматически. Старые объекты удалять после проверки переноса и ссылок.
Вложения сообщений и результаты агента остаются частями переписки. Их общие механизмы хранения нужны и сохраняются.
Глобальную базу знаний Fastkore/компании оставить в разделе «Общие знания» как справочную информацию установки. Её перенос в библиотеку в первую поставку не входит.

4. КАК АГЕНТ РАБОТАЕТ С БАКЕТОМ

MinIO хранит приватные оригиналы. База приложения связывает folderId, относительный путь, размер, хеш и объект. Ключи объектов генерирует сервер. Абсолютные пути компьютера пользователя агенту не нужны.
Оригиналы хранятся только в MinIO. Локальный каталог копий на сервере не создаётся. Поиск выполняется по серверному индексу (FTS в базе библиотеки), чтение — диапазонами из объекта MinIO по сохранённым отметкам строк. Извлечённый текст документов хранится в индексе вместе с картой страниц, разделов, листов и ячеек.
Индекс хранится по хешу содержимого: неизменённые файлы при обновлении повторно не извлекаются и не индексируются, одинаковое содержимое не дублируется.
Всё работает в Docker: с компьютера пользователя — только браузер; приложение принимает, хранит и индексирует; агент в контейнере исполнителя получает только фрагменты через инструменты библиотеки и не имеет доступа к MinIO и базе.
Текстовые исходники сохраняют дерево путей и строки. PDF, DOCX, XLSX/CSV получают извлечённый текст с картой соответствия исходному документу.

Схема работы:
компьютер пользователя → проверка и загрузка → MinIO → индексация → инструменты библиотеки → нужные фрагменты в контексте агента → ответ.

Инструменты агента:
- library_list — доступные папки проекта, назначение, состояние, покрытие.
- library_tree(folderId, path, cursor) — постраничное содержимое каталога.
- library_search(folderId?, query, pathPrefix?, mode, cursor) — поиск по именам файлов или содержимому с путями и местами совпадений. Без folderId область ограничена всеми папками, разрешёнными текущему специалисту в текущем проекте.
- library_read(folderId, fileId/path, startLine, lineCount) — фрагмент и продолжение. Для документов и таблиц возвращаются также разделы, страницы, листы и ячейки.

Пример «Откуда берётся скидка»: агент смотрит папки, ищет слово или идентификатор, читает найденный код и контекст, ищет вызываемую функцию в другой разрешённой папке, отвечает с основаниями. Весь каталог в запрос модели не включается.
Точный поиск идентификаторов, имён и текстов ошибок выполняется по существующему FTS с построчной проверкой. Поиск по регулярным выражениям (rg по извлечённому тексту) рассматривается только если контрольные вопросы покажут его необходимость. Векторная БД и предварительный разбор символов не обязательны. Документы требуют извлечения текста.
MinIO не ищет по содержимому объектов как файловая система. Поиск идёт по индексу сервера. Полное скачивание бакета на каждый вопрос запрещено как способ реализации.
Агент не получает S3-ключи и произвольный shell сервиса библиотеки. Проверка прав ограничивает каталог до поиска. Пути и ссылки не позволяют выйти за разрешённый корень.
Начальные пределы ответа сохранить — дерево до 200 записей, поиск до 20 совпадений, чтение до 200 строк и до 32 КиБ UTF-8 на ответ инструмента. При сокращении доступно продолжение. Поиск ограничен по времени и объёму работы.

5. ВНУТРЕННИЕ СОСТОЯНИЯ И АКТУАЛЬНОСТЬ

Сохранить механизм снимков для атомарной публикации как внутренние состояния библиотеки. У папки одно текущее и не более одного готовящегося обновления. Пользовательской истории, выбора прежних состояний и отката к ним нет.
Предыдущее состояние после переключения недоступно новым заданиям. Его данные удаляются, когда завершаются уже начатые чтения. Временные остатки после сбоев очищаются, объекты актуального состояния сохраняются.
В начале вопроса агент получает ссылку на готовый каталог и может закончить работу с ним. Следующий вопрос использует актуальные материалы.
По прямому решению владельца удалить проверку изменения содержимого перед публикацией. Отказ публикации из-за обновления, автоматический повтор ответа и сообщение «источник обновился, повторите вопрос» не требуются. Редкое совпадение ответа с обновлением допускается.
Проверки прав выполняются независимо от обновления файлов. Отзыв доступа продолжает блокировать чтение и выдачу закрытых материалов.
При смене содержимого старые сырые фрагменты из сессии модели не должны служить основанием следующих ответов. При необходимости начать новый контекст с опубликованной перепиской и актуальной библиотекой. Старые ответы сохраняются. Их ссылки не открывают удалённые оригиналы и не подменяют прежнее основание новым файлом без обозначения изменения.

6. ЗАГРУЗКА И ОБНОВЛЕНИЕ

В первой поставке папки создаёт локальный администратор. Он назначает управляющего папкой для добавления, обновления и удаления файлов. Сотрудник использует разрешённые материалы через назначенного специалиста.
«Загрузить папку» сохраняет относительные пути.
«Добавить файлы» строит состав текущая папка плюс добавления/замены по тому же пути. Остальные материалы сохраняются.
«Обновить из папки» считает выбранный каталог полным актуальным составом. Новые файлы добавляются, изменённые заменяются, отсутствующие удаляются. Перед применением показать количества и получить подтверждение операции.
«Удалить файл» доступно управляющему из списка с подтверждением. Изменения общей папки действуют во всех подключённых проектах, это видно перед подтверждением.
«Продолжить загрузку» использует существующую сессию и подтверждённые части после повторного выбора папки. Если состав изменился, показать конфликт и возможность отменить незавершённую операцию.
Сравнение выполняется по путям и хешам. Неизменившиеся файлы повторно не передаются. При совпадении показать «Библиотека актуальна», не создавать состояние и не запускать обработку заново. При изменении состава переиспользовать извлечение неизменившихся файлов, если обработчик не менялся.

На папку допускается одна операция до завершения подготовки/публикации или отмены. Вторая получает 409 «Папка уже обновляется. Продолжите или отмените текущую загрузку». Это касается загрузки, добавления и удаления файлов.
Операция помнит исходное текущее состояние. При завершении отклоняется, если основа изменилась. Слияния и очереди обновлений одной папки не делать. Повторы собственных запросов идемпотентны.
Передача потоковая/частями, сервер проверяет размер и SHA-256. Сбой сохраняет прежний рабочий каталог. Неподдерживаемые форматы и ошибки извлечения видны по файлам. Можно повторить обработку либо явно принять состав с обозначенным неполным покрытием.

7. ФИЛЬТРЫ И ЛИМИТЫ

Для исходников сохранить исключения DLL/EXE/PDB, готовых пакетов, bin/obj, зависимостей и кешей. Для клиентских документов использовать профиль документов, который не отбрасывает значимые материалы только из-за названия каталога. Правила и исключённые файлы видны до отправки, правила можно изменить.
Сохранять исходники, файлы проектов, конфигурацию и описания. Загрузка выполняется только через браузер. Проверки браузера и сервера должны быть согласованы. Потенциальный секрет исключается по умолчанию либо допускается явным аудируемым решением управляющего. Полное обнаружение секретов не гарантируется.
Начальные настраиваемые пределы сохранить из реализации — 50 000 файлов, 100 МиБ на файл, 20 ГиБ актуального состава папки. Это пределы допуска, а не подтверждённая производительность. Приёмка проводится на реальных Dev и небольшом наборе документов, без синтетического прогона 10 ГиБ.
Логический размер нового состава проверять целиком. Дополнительное физическое место резервировать после сравнения только для недостающих объектов с учётом конкуренции других папок. Сервер проверяет существование и принадлежность переиспользуемых объектов. Отдельно учитывать место оригиналов, извлечённого текста и кеша. При нехватке места отказать до передачи и сохранить актуальное содержимое.

8. ОБРАБОТКА ФОРМАТОВ И ЗАВИСАНИЕ

Обязательны TXT/Markdown, текстовые исходники и конфигурация, PDF с текстовым слоем, DOCX, XLSX и CSV. Извлечение полное в установленных пределах, сокращения отмечаются.
В PDF сохранять страницы. В DOCX — заголовки, абзацы и таблицы без выдуманных страниц. В XLSX — имя листа, диапазон ячеек, строки и названия/буквы колонок. В CSV — строки и заголовки колонок. В коде — относительный путь и строки. Основания поиска сохраняют связь с оригиналом.
PDF без текста получает статус «Требуется распознавание». OCR и дополнительные форматы добавляются отдельно по потребности.
Первая техническая работа — диагностировать зависание Platform на уже загруженных объектах. Указатели на тестовый MinIO и БД в work/project-sources-review/dev-index-handoff.json. Перед продолжением проверить актуальное состояние, повторная загрузка без необходимости не нужна.
Гипотеза о регулярных выражениях не подтверждена. В symbolsOf уже есть запрет анализа строк длиннее 2000 символов. Добавление такого же условия не доказывает исправление. Найти проблемный файл/участок профилированием, проверить длинные строки, извлечение и запись индекса.
Для каждого файла нужны бюджет времени и памяти, статус «Таймаут» и действие «Повторить». Синхронную CPU-работу выполнять в прерываемом worker/process с наблюдением извне. Один setTimeout в заблокированном потоке проблему не решает. После таймаута обработчик продолжает остальные файлы, интерфейс и heartbeat остаются отзывчивыми.
Разбор символов убрать из обязательного пути подготовки. Первоначальное исследование исходников обеспечивают поиск и чтение.

9. КАЧЕСТВО ПОИСКА

Заранее подготовить 10–15 вопросов по разрешённым реальным материалам с ожидаемыми файлами и основаниями. Включить точное обозначение/ошибку, формулировку другими словами, несколько документов, таблицу, обновлённый/удалённый файл, вопрос без ответа и недоступный материал. Агент может подготовить вопросы, владелец подтверждает предметные ожидания.
Сначала измерить текущий поиск и способность агента уточнять запросы. Фиксировать найденное основание, правильность ответа, ссылку и время. Если необходимые основания не находятся, добавить улучшение и сравнить на тех же вопросах. Семантический поиск вводить при подтверждённой пользе. При внешнем сервисе учесть передачу туда клиентских материалов.
Ответ опирается на найденное содержимое. При нехватке сведений или неполном покрытии агент сообщает ограничение. Текст файлов не меняет полномочия и инструкции.

10. ПРАВА И РЕЖИМ ПЕРВОЙ ПОСТАВКИ

Использовать существующие роли, членство в проектах и подключения специалистов. Папки не открываются всем специалистам автоматически. Сервер ограничивает списки, дерево, поиск, чтение и оригиналы до выдачи данных.
Отдельно задаются использование через агента, просмотр и скачивание. Управляет разрешениями администратор или уполномоченный управляющий, не модель.
Сохранить режимы «Только объяснение» по умолчанию и «Короткие цитаты». Они не предоставляют право скачать оригинал.
В этой поставке закрытый анализ выключен. Закрытые папки можно хранить и подготавливать, но агенту они недоступны с понятным объяснением статуса. Общую библиотеку принимать на материалах, разрешённых участникам тестового проекта. Исходники Fastkore не делать общедоступными для обхода блокировки.
Включение анализа материалов, недоступных сотруднику напрямую, — отдельный следующий этап с проверкой исполнителя, сохранённых сессий, журналов и каналов выдачи. Проверенные ограничения сохраняются. Отсутствие этого режима не блокирует выпуск общей библиотеки, но сценарий закрытой поддержки считается отложенным.

11. ПЕРЕНОС ДАННЫХ И ЭКСПЛУАТАЦИЯ

На проверенном действующем app отсутствуют sources и sources.sqlite. Перед выпуском повторно проверить этот факт, поскольку внешний агент продолжает работу.
При отсутствии рабочих данных новой подсистемы использовать чистую схему library и разовый перенос уже загруженных Dev из тестового MinIO. Универсальный мастер миграции и разрешения конфликтов исторических версий не создавать. Сверить объекты и хеши, тестовые оригиналы удалять после подтверждённого переноса и завершения диагностики.
Отдельно проверить ProjectFilesDialog, проекты, чаты и общие знания. Отсутствие sources.sqlite не означает отсутствия этих данных. Сохранность содержимого, ссылок и прав проверить до удаления прежней проектной библиотеки.
Удалить неиспользуемые версии, наборы, даты, историю закреплений, анализаторы, правила исторического удержания, маршруты и соответствующие настройки. Очистку бесхозных объектов незавершённых операций сохранить.
Убрать локальную утилиту загрузки tools/source-upload.mjs, токены загрузки fksrc1, их обход авторизации в server/app.ts и блок «Локальная утилита загрузки». 12. ПОРЯДОК И КРИТЕРИИ ПРИЁМКИ

Этап 1. Проверить актуальный код, устранить зависание и довести оба Dev до конечного состояния на сохранённых данных.
Этап 2. Упростить модель до текущего/готовящегося состояния, переименовать подсистему в library, объединить библиотеку проекта, завершить обновления и разовый перенос с сохранением прав.
Этап 3. Завершить DOCX, проверить PDF/XLSX/CSV, основания ответов и поиск на 10–15 вопросах. Улучшать поиск по измеренным ошибкам.
Этап 4. Проверить интерфейс в браузере на базе Chromium, сборку, релевантные тесты, развёртывание и восстановление. Проверка закрытого исполнения — отдельный этап.

Приёмка первой поставки:
- Есть «Проекты» и «Библиотека», один экран материалов проекта и отдельные «Общие знания».
- Оба Dev обрабатываются до конечного состояния с видимыми пропусками/ошибками. Трудный файл не останавливает сервис.
- Основные форматы доступны для поиска с корректными ссылками на исходный материал.
- После обрыва передача продолжается. Неизменившаяся папка не создаёт дублей и повторной обработки.
- Обновление корректно добавляет, заменяет и удаляет. Добавление отдельных файлов сохраняет остальные, удаление из UI соблюдает права.
- Параллельное обновление одной папки даёт 409. Сбой сохраняет текущий состав, публикация нового состава согласована.
- Агент исследует дерево, ищет и дочитывает контекст без скачивания всего бакета на каждый вопрос. Следующий вопрос использует актуальную библиотеку. Проверки изменения содержимого перед публикацией нет.
- Права проектов/специалистов и запрет оригиналов действуют на сервере. Закрытый анализ выключен.
- Резервная копия восстанавливается. В продуктовых API и UI отсутствуют исторические версии и прайсы по датам.
- По каждому контрольному вопросу записан результат и ограничение. Отчёт исполнителя и независимая приёмка разделены.

После каждого этапа обновлять TODO — файлы, проверки, результаты, ограничения и следующий шаг. Сохранять чужие изменения рабочего дерева. Код и секреты клиента, сырые журналы закрытых материалов в отчёт не включать.
