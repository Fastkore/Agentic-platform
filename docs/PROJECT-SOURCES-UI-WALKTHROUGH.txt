ИСТОЧНИКИ ПРОЕКТА — РУЧНОЙ ПРОХОД ИНТЕРФЕЙСА
Скриншоты: docs/project-sources-screens/ (искусственные данные, тестовое локальное хранилище, без секретов и личных данных).
Снято в Chrome headless 1400×950, тёмная тема, на сборке исполнителя от 17.11.2026.

Подготовка: сервер с настроенным хранилищем источников (BRIDGE_SOURCES_S3_* либо BRIDGE_SOURCES_STORAGE=filesystem вне production),
руководитель с локальным входом, проект с участником-сотрудником. Тестовая папка: Business/{Orders/Discount.cs, Docs/README.md, appsettings.json, .git/config}.

1. Создание источника. Проект → ⋮ → «Источники проекта» (01). «Создать источник»: название, назначение, тип, классификация, выдача (02) →
   «Создать и подключить». Источник появляется в реестре и в проекте; специалистам доступа нет.
2. Загрузка каталога. «Новый снимок» → «Выбрать папку…» (03). Браузер проверяет папку: файлы, объём, исключения (.git), ошибки путей,
   возможные секреты (appsettings.json исключён по умолчанию) (04). Ввести версию «27.0.48» → «Проверить на сервере»: сколько передать,
   сколько не изменилось, отличия от базового снимка (05) → «Начать передачу» → «Передача файлов» и «Подготовка для агента» (06).
   Проверка возобновления: закрыть вкладку во время передачи, открыть снова, «Новый снимок» → «Продолжить» → выбрать ту же папку.
3. Выбор версии. В карточке источника выбрать «27.0.48» (07). Состояние, покрытие, назначенные специалисты видны в карточке.
4. Назначение. Вкладка «Связи»: включить переключатель в ячейке «Fastkore Business × Помощник Фасткор»; кнопка (i) показывает
   эффективный доступ и причину недоступности (08). То же из «Специалисты проекта» → кнопка «Источники» у специалиста (15, 16).
5. Пара версий. Загрузить второй источник (Platform), в «Настройки → Источники → источник → Снимки» подтвердить совместимость
   («Совместим с»), затем вкладка «Наборы версий» → «Новый набор версий» → «Создать и сделать активным» (09).
   Несовместимая пара отклоняется с объяснением.
6. Прайсы и даты. Вкладка «Даты»: часовой пояс и правило текущей бизнес-даты (10). Для источника типа «Прайс-листы» при загрузке
   указывается «Действует с/до»; в карточке отмечаются допущенные периоды, пересечения и пробелы показываются предупреждением.
7. Вопрос. Сотрудник задаёт вопрос в чате проекта. Ответ содержит основание: источник, версию, путь и строку; в заголовке чата —
   индикатор набора версий (11). Режим «Только объяснение» не выводит исходный текст; ответ показывается после серверной проверки.
8. Отказ скачивания. Сотрудник без view/download_original не видит реестр и маршрут оригинала (404). Руководитель скачивает
   оригинал только через административный маршрут.
9. Обновление и откат. Загрузить снимок 27.0.49 (неизменившиеся файлы не передаются), выбрать его в карточке или в новом наборе.
   Начатый чат остаётся на прежней версии и показывает «в проекте: …» с кнопкой «Переключить чат». Откат — выбрать прежний
   набор и «Сделать активным».
10. Реестр. «Настройки → Источники»: хранилище, обработчики, реестр (12); карточка источника: где используется, снимки,
    «Подготовить заново», «В архив», архивирование и удаление с перечнем препятствий (13).
11. Локальная утилита. «Настройки → Источники → источник → Локальная утилита загрузки» → «Выдать токен» (14; на скриншоте токен
    замаскирован). Запуск: FASTKORE_SOURCES_TOKEN=… node tools/source-upload.mjs --server … --source … --label … --dry-run ПАПКА,
    затем без --dry-run. Повторный запуск после обрыва продолжает загрузку; «Отозвать токены» прекращает доступ утилиты.
