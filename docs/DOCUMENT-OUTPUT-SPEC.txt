1. ЦЕЛЬ

Специалист отвечает не только текстом, но и готовым файлом, который сотрудник проверяет и отправляет клиенту без доработки оформления:
- коммерческое предложение — DOCX и PDF с одинаковым видом, и/или XLSX с расчётом и печатной формой;
- расчёт трудоёмкости и стоимости — XLSX с формулами;
- письма, пояснительные записки, спецификации, сравнения, приложения — DOCX, XLSX, PDF.
Если есть образец — документ повторяет его оформление (стили, колонтитулы, логотип, реквизиты, структуру); если нет — аккуратное нейтральное оформление. Файл появляется в ответе, скачивается и (этап 4) просматривается в чате.

2. ЧТО УЖЕ ЕСТЬ (проверено по коду c808989)

- Задание с записью: инструмент специалиста «Вложения и файлы ответа», разрешение записи в общих настройках и в профиле, изолированный исполнитель (BRIDGE_EXECUTION=isolated, папка заданий). Агенту доступна командная строка без сети; запись только в папку задания.
- Вход: вложения чата и недавние результаты копируются в input. Выход: файлы из output прикрепляются к ответу — до 8 файлов, 20 МБ на файл, 60 МБ на ответ; при ошибке задания созданные файлы удаляются.
- Образ исполнителя (Dockerfile.codex): только Node и CLI моделей. Нет Python, библиотек DOCX/XLSX, конвертера в PDF и шрифтов с кириллицей.
- Ограничения контейнера codex: mem_limit 1g на всех, pids_limit 128 (считаются и потоки), корень только для чтения, /tmp 64 МБ noexec, собственный seccomp-профиль, сеть только к API моделей.
- Если в задании подключена папка библиотеки в режиме «Только объяснение», запись файлов отключается полностью (protectSourceFiles): содержимое файлов не проверяется проверкой публикации.
- skillIds в профиле не реализованы («Профиль ожидает установки и проверки утверждённых Skills»).

3. ВЫБОР ИНСТРУМЕНТОВ

Требование владельца: только проверенные, широко применяемые решения; новые и не обкатанные наборы не используются.

Что применяют агентные системы с изолированным исполнением (обзор 18.11):
- ChatGPT (анализ данных, бывший Code Interpreter): Python-песочница без сети; файлы Word и Excel собираются python-docx и openpyxl.
- Open WebUI: стандартный образ для создания файлов содержит python-docx, python-pptx, fpdf, openpyxl, Pillow.
- Навыки OpenAI для Codex (каталог openai/skills, curated): doc — python-docx, проверка вида через LibreOffice→PDF→PNG (Poppler); spreadsheet — openpyxl, формулы и форматирование; pdf — reportlab, pdfplumber, pypdf, визуальная проверка страниц через Poppler. Лицензии — по LICENSE.txt в папке каждого навыка (Apache-2.0 или MIT; кроме навыков Figma). Каталог openai/skills помечен устаревшим и указывает на openai/plugins; используем закреплённый снимок.
- Навыки Anthropic для Claude (docx, xlsx, pdf): DOCX — библиотека docx (npm), XLSX — openpyxl и pandas; LibreOffice в фоновом режиме — пересчёт формул и перевод в PDF; Poppler (pdftoppm) — страницы PDF в изображения для самопроверки.
- Серверная конвертация в продуктах (например, Documenso): Gotenberg — открытый (MIT) HTTP-сервис, внутри которого тот же LibreOffice.
Вывод: стандарт де-факто — openpyxl и python-docx для сборки, LibreOffice для PDF и пересчёта формул, Poppler для проверки; навыки OpenAI построены ровно на этом наборе. Это зрелые открытые проекты с многолетней историей.

Альтернативы и почему не основной путь:
- WeasyPrint, Chromium (HTML→PDF): хороши для PDF из HTML, но PDF не совпадает с DOCX и не пересчитывает XLSX — только запасной путь для отчётов «только PDF».
- ReportLab, fpdf2: PDF «с нуля» кодом; вёрстка таблиц и кириллицы трудоёмка, вид отличается от Word.
- Microsoft 365 (Graph): лучшее совпадение с Word, но документы уходят в облако Microsoft и нужна подписка.
- Aspose: высокое качество без LibreOffice, платная серверная лицензия.

Решение:
- В исполнителе: Python 3, openpyxl, python-docx (сборка), LibreOffice (PDF, пересчёт), Poppler (проверка), шрифты. LibreOffice — внутри исполнителя, а не отдельным сервисом: у задания нет сети, и вынос конвертации наружу потребовал бы открыть путь из песочницы.
- На платформе (этап 4, просмотр в чате): Gotenberg или тот же LibreOffice в отдельном контейнере без внешней сети — конвертирует уже выданные файлы для предпросмотра.
- Отчёты Fastkore: если у специалиста есть инструмент Fastkore ERP, агент может запустить формирование отчёта через CLI и приложить его PDF или объединить с собственным документом (pypdf). Это дополнительный путь; он не заменяет собственный набор инструментов.

4. СОСТАВ ИСПОЛНИТЕЛЯ

Состав образа исполнителя, версии закрепить:
- Python 3 из Debian; библиотеки openpyxl, python-docx, lxml, Pillow, matplotlib (диаграммы), pypdf (объединение, разделение PDF), reportlab (PDF с нуля, навык pdf), pdfplumber (чтение и проверка PDF), pdf2image (рендер страниц для навыков doc и pdf) — устанавливаются при сборке образа в отдельное окружение с закреплёнными версиями и хешами (pip --require-hashes); pip во время задания недоступен;
- libreoffice-writer-nogui, libreoffice-calc-nogui — DOCX→PDF, XLSX→PDF, пересчёт формул XLSX, DOC/XLS→DOCX/XLSX;
- poppler-utils — pdftotext для проверки текста PDF, pdftoppm для изображений страниц;
- шрифты: только свободные, с кириллицей, около 10 семейств без изысков, из пакетов Debian:
  Liberation Sans / Serif / Mono (метрически совместимы с Arial, Times New Roman, Courier New) — fonts-liberation2;
  Carlito (Calibri), Caladea (Cambria) — fonts-crosextra-carlito, fonts-crosextra-caladea;
  PT Sans, PT Serif, PT Mono — fonts-paratype;
  DejaVu Sans / Serif — fonts-dejavu-core;
  Open Sans — fonts-open-sans; Roboto — fonts-roboto-unhinted.
  Несвободные шрифты в образ не включаются (решение владельца 18.11).
Замена шрифтов образца: если шрифт образца не входит в набор, агент заменяет его свободным по таблице fontconfig (Arial→Liberation Sans, Times New Roman→Liberation Serif, Courier New→Liberation Mono, Calibri→Carlito, Cambria→Caladea, прочие без засечек→PT Sans, с засечками→PT Serif) и до выдачи предупреждает сотрудника в ответе: какой шрифт образца заменён и на какой. В DOCX записывается шрифт замены, чтобы Word и PDF совпадали.
Прочие пакеты не ставить. Агент не устанавливает пакеты во время задания.
Тексты навыков Anthropic распространяются по собственной лицензии и не копируются; используются только как ориентир.

Обёртка fk-office (скрипт в образе) для вызова LibreOffice:
- отдельный профиль пользователя и TMPDIR внутри папки задания (корень и /tmp не используются);
- не более 2 конвертаций одновременно на исполнитель (блокировка), тайм-аут 120 с, принудительное завершение процесса;
- команды: to-pdf <файл>, recalc <xlsx> (JSON: число формул и ошибок с адресами), convert <файл> <формат>, pages <pdf> (PNG страниц для просмотра).

Ограничения контейнера: mem_limit — 3 ГБ; pids_limit — ориентир 512 с проверкой на стенде. В seccomp добавить только системные вызовы, которые реально нужны LibreOffice и Python. Песочницам моделей дать право чтения каталогов Python, LibreOffice и шрифтов. Изоляция и запрет сети сохраняются. Рост образа зафиксировать в отчёте.

5. ОБРАЗЦЫ (РЕФЕРЕНСЫ)

Платформа не хранит шаблонов и фирменных наборов. Образцами служат обычные файлы пользователя:
- вложения в сообщении — уже попадают в input/attachments;
- файлы библиотеки — папки, подключённые к проекту и назначенные специалисту (бывшие «Файлы проекта» теперь тоже папка библиотеки).

Сейчас агент читает файлы библиотеки только как извлечённый текст (library_read): стили, колонтитулы, логотип и таблицы оригинала ему недоступны. Нужен инструмент library_copy:
- копирует оригинал выбранного файла из MinIO в input/library/<папка>/<путь> текущего задания;
- только DOCX, XLSX, PPTX, PDF и изображения, до 20 МБ на файл и 60 МБ на задание, не более 10 файлов;
- только из папок с режимом «Короткие цитаты» и только для заданий с записью; папки «Только объяснение» и закрытые — отказ с понятной причиной (исходники и закрытые материалы не копируются);
- права проверяются при каждом вызове, как у library_read; копирование пишется в журнал (папка, файл, задание) без содержимого;
- копия живёт только в рабочей папке задания и удаляется вместе с ней; в ответ попадает только то, что агент собрал в output, и оно проходит проверку раздела 7.
Чтобы образцы КП можно было брать за основу, папку с ними ставят в режим «Короткие цитаты».

Навык documents-by-reference (содержание):

Образец:
- Если сотрудник указал образец — взять его. Иначе найти: вложения сообщения, затем библиотека (library_search mode=files по «КП», «коммерческое», названию клиента или типу документа; затем по содержанию). Если подходящих несколько — взять самый свежий и назвать его в ответе; если образца нет — сказать об этом и сделать нейтральное оформление.
- Образец из библиотеки копировать library_copy; изучить: стили, поля, колонтитулы, логотип и изображения, структуру разделов, таблицы, формат сумм и дат; для XLSX — листы, стили ячеек, формулы, печатные настройки.
- Собирать новый документ на основе копии образца (открыть, очистить содержимое, сохранить стили, колонтитулы и изображения), а не воссоздавать оформление с нуля. Данные и тексты образца (другой клиент, суммы, даты) в новый документ не переносить.

Сборка:
- DOCX — python-docx на основе образца (или с нуля, если образца нет): стили документа, а не ручное форматирование каждого абзаца; заголовки стилями «Заголовок 1–3», таблицы стилем таблицы, «не отрывать от следующего» у заголовков, повтор шапки таблицы на каждой странице, строки таблиц не разрываются, нумерация страниц, колонтитулы с логотипом и реквизитами; без пустых абзацев для отступов.
- XLSX — openpyxl на основе образца (или с нуля): итоги и производные значения — формулами; форматы денег («# ##0,00 ₽»), процентов и дат; ширина колонок по содержимому; закреплённая шапка; печатная область, «вписать по ширине», колонтитулы, логотип на печатной форме; после сборки fk-office recalc — ноль ошибок формул.
- PDF — только конвертацией готового DOCX или XLSX через fk-office to-pdf, чтобы PDF совпадал с Word/Excel. Объединение с другими PDF (например, отчётом Fastkore) — pypdf.
- Диаграммы — matplotlib в цветах образца, PNG 200 dpi, вставка в DOCX; в XLSX — встроенные диаграммы openpyxl.

КП (структура по умолчанию, если образца нет; при образце — структура образца): титул или шапка (логотип, «Коммерческое предложение», клиент, номер, дата), краткое резюме предложения, задача клиента, предлагаемое решение, состав работ и этапы, сроки, стоимость (таблица с итогом и НДС по указанию сотрудника), условия, что не входит, контакты. В XLSX-версии — лист «КП» (печатная форма) и лист «Расчёт» с формулами, на которые ссылается печатная форма.

Типографика без образца: одно семейство шрифтов, 3–4 размера; цвет — только для заголовков, шапок таблиц и акцентов; числа и суммы выравниваются вправо, разряды разделяются пробелом; даты «18 ноября 2026 г.»; не более одного акцентного цвета на странице; поля не меньше 2 см.

Проверка перед выдачей:
- файл открывается библиотекой заново; fk-office recalc без ошибок;
- PDF переводится в изображения страниц (fk-office pages), агент просматривает их и исправляет: «висячие» заголовки, разорванные таблицы, вылезающий текст, пустые страницы, неверные переносы, «квадратики» вместо букв;
- извлечённый текст не содержит меток [уточнить], «TODO», «Lorem», служебных путей и данных из образца (имя прежнего клиента, его суммы и даты); суммы в тексте совпадают с таблицей; одинаковые суммы в DOCX, XLSX и PDF одного комплекта;
- имя файла по-русски и по смыслу: «КП_<Клиент>_<дата>.docx/.pdf/.xlsx», «Расчёт_<Проект>_<дата>.xlsx»; не более 8 файлов, скрипты и промежуточные файлы в output не класть.
- В тексте ответа: состав комплекта, какой образец взят за основу, на каких данных основан, что требует проверки сотрудником (цены, условия, неподтверждённые места).
Содержание КП определяют инструкции специалиста («Подготовка КП», «Оценщик»); навыки отвечают за правильную сборку и оформление.

7. ПРОВЕРКА ФАЙЛОВ ПЕРЕД ВЫДАЧЕЙ

Файлы из output проходят ту же проверку публикации, что и текст ответа, когда в задании есть папки библиотеки:
- текст извлекается теми же обработчиками, что и в библиотеке (DOCX, XLSX, PDF, текст); прочие форматы при подключённой библиотеке не выдаются (архивы, изображения, исполняемые файлы) — с понятной причиной в ответе;
- режим «Только объяснение»: в файле не должно быть кода, блоков исходного текста, длинных дословных фрагментов источников (как для ответа); «Короткие цитаты» — короткие цитаты допустимы;
- нарушение — файл не публикуется, сотрудник видит причину; в журнал пишется событие без содержимого.
После этого запрет записи при подключённой библиотеке (protectSourceFiles) снимается для открытых папок; для закрытых (restricted) остаётся.

8. ПРОСМОТР В ЧАТЕ (этап 4)

- PDF — встроенный просмотр в браузере.
- DOCX и XLSX — просмотр через PDF, который делает контейнер конвертации платформы (Gotenberg или LibreOffice без внешней сети), кэш по хешу файла.
- Скачивание оригинала без изменений.

9. ЭТАПЫ И КРИТЕРИИ ПРИЁМКИ

Этап 1. Инструменты исполнителя.
- Образ собирается; замер размера; app и codex стартуют; тесты платформы проходят. Сборку, запуск и замеры на стенде выполняет владелец по инструкции исполнителя.
- В задании с записью агент выдаёт DOCX, XLSX и PDF (по образцу из вложения); файлы открываются в Word и Excel; кириллица в PDF без «квадратиков»; формулы пересчитаны; страницы PDF переводятся в изображения.
- Параллельно 4 задания с конвертацией в PDF не превышают лимитов памяти и процессов; тайм-аут конвертации срабатывает и не оставляет процессов.
- Без записи и без инструмента «Вложения и файлы ответа» поведение прежнее. Сеть в задании по-прежнему закрыта.

Этап 2. Запись при подключённой библиотеке и образцы из библиотеки.
- Проверка файлов из output по разделу 7. Автотесты: DOCX/XLSX/PDF с кодом из источника, длинной цитатой и base64 блокируются в режиме «Только объяснение»; с именами полей и команд — проходят.
- Специалист с подключённой открытой папкой выдаёт файл; с закрытой — запись по-прежнему отключена.
- library_copy: копирует DOCX/XLSX из папки «Короткие цитаты»; отказывает для «Только объяснение», закрытых папок, исходников и сверх лимитов; права проверяются при каждом вызове; запись в журнале.

Этап 3. Навыки и сборка по образцу.
- Навыки OpenAI doc, spreadsheet, pdf и documents-by-reference в образе; skillIds в профиле работает; специалист без отмеченных навыков их не получает.
- Визуальная самопроверка по изображениям страниц работает в исполнителе.
- Приёмка владельцем: образцы КП в библиотеке проекта; 3 контрольных КП (простое, с этапами и диаграммой, с расчётом в Excel) — каждое в DOCX, PDF и XLSX; плюс одно КП без образца. Критерии: оформление повторяет образец; данные прежнего клиента не просочились; можно отправить клиенту без правки оформления; DOCX и PDF выглядят одинаково; суммы во всех файлах совпадают; формулы в XLSX живые.

Этап 4. Просмотр PDF/DOCX/XLSX в чате.

Для каждого этапа: отчёт исполнителя и независимая приёмка раздельно. Контрольные запросы: КП (3 по образцу и 1 без), расчёт трудоёмкости, письмо клиенту, спецификация, таблица сравнения — с записью: что получил сотрудник, открывается ли файл, верны ли данные, годится ли оформление для клиента.

10. ВНЕ ОБЪЁМА
