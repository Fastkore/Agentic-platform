# Пилот входа Fastkore · 0.6.0

Наша часть этапа 3 реализована по проекту контракта v1. Это кандидат для совместной проверки, а не подтверждение готовности ERP-интеграции. На действующем офисном сервере SSO выключен. Адрес Linux, сертификат, фактические ERP-методы и WPF-клиент ещё ожидаются.

## Что реализовано

- Доверенные установки из локальной серверной конфигурации; браузер не задаёт URL проверки или секрет.
- Обмен формы POST с одноразовым билетом, онлайн-проверка HTTPS без перенаправлений и повторов; лимит ответа 8 КБ, общий тайм-аут 5 секунд.
- Уникальная личность `(installation_id, external_user_id)`, самостоятельные права платформы, первый вход без пароля и без проектов/рабочей роли.
- Cookie `__Host-bridge_session`: Secure, HttpOnly, Path=/, SameSite=Lax, 30 минут. В SQLite сохраняется хеш, значение не возвращается в JSON/JavaScript.
- CSRF для всех изменяющих cookie-запросов: обязательны точный Origin и X-Bridge-CSRF. API Bearer используется отдельно; смешанный вход отклоняется.
- Отзыв сеансов/ключей при блокировке пользователя, отключении установки или смене внешней связи. Выход отзывает текущий сеанс и удаляет cookie.
- Административный просмотр установок, выключение/включение входа и явная привязка ERP-личности к существующему пользователю в разделе «Команда».
- Приём `fastkore.context` через chrome.webview, проверка типа объекта на сервере, показ объекта и создание связанного чата по кнопке. Получение контекста не отправляет вопрос и не меняет объект прежнего чата.

SQLite обновляется до user_version=2: добавлено устойчивое хранение хешей предъявленных билетов и состояния установок. Старые проекты, сообщения и учётные данные сохраняются. Версия 0.5 не открывает БД версии 2; откат требует резервной копии всей папки данных, сделанной при остановленном сервере перед обновлением.

## Обязательные ограничения пилота

SSO включается только при `BRIDGE_EXECUTION=disabled`, настроенном HTTPS origin и конкретном доверенном proxy. Это проверяется при запуске. Причина: изоляция агентов от корпоративных секретов ещё относится к следующему этапу. Нельзя снимать этот запрет для подключения закрытых данных. Обычный офисный режим без SSO сохраняет прежнюю работу.

Реальная одноразовость и срок 60 секунд гарантируются методом Fastkore validate-ticket. Дополнительно платформа атомарно регистрирует хеш билета **до** запроса к ERP на 5 минут, в том числе после перезапуска; неоднозначный ответ требует нового билета. Невалидный/погашенный билет не принимается локально, другой ИИ не вызывается.

30 минут — предложенный срок для согласования. Блокировка только в ERP не отзывает уже созданную cookie немедленно: нужны истечение, следующий вход либо отдельный согласованный канал отзыва. В этой версии такого канала нет.

## Настройка на тестовом сервере

1. Сначала настройте локального администратора платформы. Первый вход через ERP не может стать первичной настройкой руководителя.
2. Поднимите HTTPS reverse proxy, закрыв прямой доступ к порту приложения. Шаблон: `deploy/nginx.conf.example`. Proxy должен **перезаписывать**, а не принимать от клиента, X-Forwarded-Proto и X-Forwarded-For. Доверяйте только фактическому адресу proxy, видимому контейнером; адрес зависит от сетевой схемы Docker.
3. Задайте BRIDGE_PUBLIC_ORIGIN, например `https://agents.company.test`, без пути и завершающего слеша. Для нестандартного порта Host должен содержать этот порт; скорректируйте proxy.
4. Создайте закрытый каталог `private/` вне web-root и библиотек проектов. Скопируйте `deploy/fastkore-sso.example.json` в `private/fastkore-sso.json`. Впишите стабильный ID установки, её HTTPS URL и согласованные типы объектов. Пример `ProductionOrder` не объявляется фактическим типом ERP. Для пилота установите enabled=true.
5. Запишите отдельный секрет проверки билетов в `private/fastkore-validation`. Предлагаемый формат: случайные 32 байта в base64url, 43 символа, без кавычек. Не используйте пароль сотрудника, OpenAI-токен или общий секрет чтения всей ERP. ERP-метод должен принимать этот секрет только для validate-ticket. Файл должен читаться UID/GID 1000 контейнера, но быть недоступен остальным; не ослабляйте права до общедоступных ради запуска. Эти файлы исключены из Git и Docker build context.
6. В .env укажите точный BRIDGE_TRUST_PROXY. Запустите `docker compose -f compose.yaml -f compose.sso.yaml up -d --build`. Overlay монтирует конфигурацию и секрет только в сервер приложения. В базовом Compose SSO выключен. При корпоративном CA настройте доверие Node через NODE_EXTRA_CA_CERTS и отдельный read-only mount сертификата; отключать проверку TLS запрещено.
7. Подтвердите health, безопасный отказ без билета, отсутствие прямого доступа к 8787 и сохранение данных после перезапуска. Linux/Compose на этой машине не проверены: выполнить эти шаги нужно на предоставленном хосте.

Для запуска сервера без Docker задайте абсолютный BRIDGE_SSO_CONFIG с тем же форматом и путём secretFile, доступным только серверу. Требования HTTPS, доверенного proxy и выключенного исполнения остаются.

Изменение серверного URL/секрета/типов требует перезапуска. Администратор может немедленно отключить вход установки в интерфейсе; включение не переопределяет enabled=false в серверном файле. В ответах администратора URL и путь к секрету не выдаются.

## Контракт для разработчика Fastkore

Согласовать приведённые форматы из `FASTKORE-SSO-CONTRACT-DRAFT.txt`. В коде платформы сейчас принимается следующий v1:

1. ERP выдаёт непрозрачный билет 32 случайных байта base64url со сроком 60 секунд для audience `fastkore-agent-platform`. Стабильные ID установки/пользователя: латиница, цифры, `_.:/-`, до 128 символов; GUID подходит. Название пользователя — до 100 символов.
2. WebView2 выполняет POST-навигацию на `https://<платформа>/auth/fastkore/exchange` с Content-Type `application/x-www-form-urlencoded`; только installation_id и ticket. Ни URL билета, ни returnUrl, ни userId/role в форме нет. Query string отвергается. Запрос с чужим Origin или Sec-Fetch-Site cross-site отвергается. Нативная навигация без этих заголовков или с Origin null/Fetch-Site none допускается; это нужно проверить в целевой версии WebView2.
3. Платформа POST-ит `{installation_id,ticket,audience}` на заранее заданный HTTPS `/api/ai/validate-ticket`, используя `Authorization: Bearer <серверный секрет>`.
4. ERP **атомарно погашает** действительный билет и отвечает application/json: `{valid:true, installation_id, audience, user:{id,display_name}}`. Роли из ERP не дают прав платформы. Отказ — valid=false либо соответствующий HTTP-код, без внутренних подробностей.
5. Платформа устанавливает cookie и отвечает 303 Location: /. При ошибке отображается безопасная страница с предложением заново открыть окно из ERP. Автоматического повтора или fallback нет.
6. После установки сессии страница сообщает хосту `{type:"fastkore.ready",version:1}`. Хост передаёт `{type:"fastkore.context",version:1,entityType,entityId,suggestedAgent?}` штатным WebView2 message API. Тип и ID объекта — стабильные значения ERP. Профиль suggestedAgent может только предложить уже разрешённого специалиста.

Хост обязан проверять точный origin платформы, ограничивать навигацию/новые окна и при выходе/смене ERP-пользователя закрывать старую страницу и очищать отдельный профиль WebView2 (cookies, storage, кэш, черновики). Наша страница предпочитает новую cookie прежнему Bearer в sessionStorage, очищает свой выбор диалога и отслеживает смену личности при запросах. Это не заменяет обязанности хоста удалить ранее загруженную страницу. Автоматического выхода из всех других браузеров пользователя нет.

## Граница приёмки

Локальные проверки используют искусственные личности и тестовый сервер. Реальная цепочка WPF → launch-ticket → HTTPS exchange → validate-ticket → рабочий объект, перезапуск Linux, офисный сертификат и смена ERP-пользователя остаются совместной проверкой. Её нельзя отметить выполненной по результатам наших тестов.

Основания: [cookie MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie), [WebView2 security](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security), [Fastify trustProxy](https://fastify.dev/docs/latest/Reference/Server/#trustproxy).
