## Открытая проблема: обрыв потокового ответа через прокси

Симптом: запрос уходит, ответа нет («вечная загрузка»), задание висит до 15-минутного таймаута платформы.

Факты из логов CLI (`…/.gemini/antigravity-cli/log/`):

```
Run: attempt 1 failed (request failed: Post
"https://daily-cloudcode-pa.googleapis.com/v1internal:streamGenerateContent?alt=sse":
unexpected EOF), retrying in 4s
```

- Обрывается именно **долгоживущий SSE-стрим** `streamGenerateContent`; CLI повторяет попытку каждые ~30–40 с.
- Короткие ответы проходят стабильно; длинные (богатый контекст, документы) — обрываются.
- Маршрут контейнера исполнителя: `HTTPS_PROXY=host.docker.internal:10809` (Happ) → выход US (IONOS/pbiaas) → Google.
- **Прямой доступ без прокси проверен — не работает** (`agy -p …` → `error: interrupted`; регион Google).
- Следовательно, обрыв происходит в цепочке Happ/Xray/выходной узел — вероятнее всего рвутся долгоживящиеся соединения (idle/stream timeout) на прокси или узле.

## Варианты решения (не реализованы)

1. **Тюнинг Happ/Xray** — увеличить таймауты простоя/стрима для `*.googleapis.com` или сменить выходной узел. Риск: перезапуск Happ кратко отключает VPN всем; конфигурация нетривиальна (TUN sing-box + xray + подписочная БД).
2. **Вынести исполнителя на VPS в поддерживаемом регионе** (обсуждается владельцем) — тогда Happ не нужен: прямой стабильный выход, патч региона остаётся в образе. Требует переноса тома `codex_auth` (аккаунты) и включения исполнителя в деплой.
3. Смягчение в платформе: сокращённый таймаут/быстрая диагностика для Antigravity — не делали, чтобы не резать легитимно долгие ответы.

## Что уже сделано для диагностики

- `geminiFailure()` различает регион/квоту/авторизацию понятными сообщениями.
- В пикере у Antigravity виден весь список моделей CLI (claude/gpt-oss могут не отвечать через coding-план — известно).
- Патч региона самопроверяется при сборке образа (SHA бинарника).

## Связанное

- GLM (Z.ai) подключён отдельным исполнителем и работает напрямую, без прокси — основная нагрузка снята с Antigravity.
- Аккаунт Antigravity остаётся активным; при переходе на VPS — перенести `codex_auth` и повторить сквозную проверку.
