ИСТОЧНИКИ ПРОЕКТА — КАНАЛЫ ВЫДАЧИ ЗАКРЫТЫХ МАТЕРИАЛОВ (AC09, AC10)
Обновлено 17.11.2026 после независимой проверки API. Полный прогон с реальным исполнителем остаётся в TODO.

1. ТЕХНИЧЕСКИ ЗАКРЫТЫЕ КАНАЛЫ (проверены автотестами)

Скачивание и просмотр оригинала
  Только административные маршруты …/files/{fileId}/original с отдельными правами view_original и download_original; сотрудник
  получает 404, делегированный управляющий без права — 403; каждое обращение пишется в аудит.
  tests/sources-api.test.ts (AC06/AC09), tests/sources-closed.test.ts (E1).
Доступ модели к хранилищу
  Исполнитель не получает S3-ключи, object keys, presigned URL и пути. Чтение выполняет процесс платформы; инструменты возвращают
  строки по относительному пути выбранного снимка. Ключи объектов генерируются сервером по шаблону sources/<id>/blobs/<id>.
  server/sources/blob-store.ts, server/sources/tools.ts.
Расширение области чтения моделью
  Источник, снимок, проект, сотрудник и специалист берутся из зафиксированной области задания (run_scopes); чужой bindingId,
  чужой fileId, «..» в пути, смена проекта параметром — отказ. Права перепроверяются при каждом вызове.
  tests/sources-api.test.ts (AC06), tests/sources-closed.test.ts.
Рабочая папка и файлы ответа
  Источники не копируются в input исполнителя. Для закрытых источников и режима «только объяснение» папка output не создаётся (workDirectoryId отсутствует,
  allowWrite=false), поэтому файл с исходником не может стать вложением ответа.
  tests/sources-closed.test.ts (E2/E4/AC10).
Поток, события, история, run API, статус
  Ответы заданий с источниками публикуются после проверки. Сырые результаты инструментов не сохраняются в Run и Message.
  Фрагменты для проверки находятся в памяти приложения в пределах задания. Миграция 4 удаляет старую таблицу run_reads.
  Для следующего вопроса создаётся новая сессия исполнителя. При совпадающей области доступа в контекст попадают прежние принятые ответы,
  а не transcript инструментов. tests/sources-api.test.ts (AC06/AC09), tests/sources-closed.test.ts.
Публикация ответа
  Перед показом: повторная проверка прав (отзыв во время задания → ответ не публикуется), запрет блоков кода, длинных
  закодированных строк (base64), цитат-фрагментов кода в обратных кавычках, дословных строк длиннее порога и листингов из трёх и
  более строк подряд; в режиме «короткие цитаты» запрещены только листинги и длинные дословные фрагменты.
  tests/sources-closed.test.ts (BLOCK, BASE64, LINES, QUOTE), tests/sources-api.test.ts (AC11).
Передача другому специалисту
  При закрытом или «только объяснение» наборе консультации специалистов в задании отключены — сырые фрагменты не уходят в контекст
  другого профиля. server/workspace.ts (specialists).
Неизвестные и чужие идентификаторы
  Реестр, матрица, привязки, загрузки и оригиналы отвечают нейтральным 404; причина пишется в аудит (source.denied).
Закрытые источники на непроверенном исполнителе
  restricted доступен только изолированному Codex при BRIDGE_SOURCES_CLOSED_ANALYSIS=verified. В этом режиме инструменты отправки
  данных через веб, ERP и другие профили недоступны. При выключенном режиме матрица показывает причину. tests/sources-closed.test.ts (E6).
Токен локальной утилиты
  Только маршруты загрузки одного источника, 5–240 минут, хранится хешем, отзывается; не выдаёт новых токенов, не открывает реестр
  и статус. tests/sources-cli.test.ts.

2. ОСТАТОЧНЫЙ РИСК (не устраняется техническими средствами платформы)

Пересказ и воспроизведение моделью
  Модель, читающая исходники, может изложить логику близко к тексту, переименовав переменные, разбив код на прозу, изменив
  форматирование или выдавая по одной строке в нескольких ответах. Проверка публикации ловит дословные совпадения и типовые формы
  (код, base64, листинги), но не доказывает отсутствие утечки. Абсолютная гарантия невоспроизведения не заявляется (ТЗ, раздел 9).
Накопление по нескольким вопросам
  Каждый ответ проверяется отдельно; последовательность допустимых ответов может раскрыть больше, чем один. Аудит source.publish
  фиксирует задания и число чтений для последующего анализа.
Внешний провайдер исполнения
  Фрагменты, прочитанные инструментом, передаются модели провайдера. Хранение сессий и журналов у провайдера определяется его
  условиями; до работы с реальными закрытыми данными это проверяет владелец (ТЗ, раздел 9).
Опубликованные ответы
  Разрешённый ответ, уже показанный сотруднику, нельзя отозвать из его памяти; история хранит исходный набор версий и не открывает
  оригиналы по новым ссылкам.
Если требуется полное исключение передачи кода модели — нужен другой режим (заранее подготовленная документация без исходников
в контексте), это отдельное изменение требований.
